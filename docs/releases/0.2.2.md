# Release 0.2.2 — 2026-09-11

助手立项与批量写入能力增强，以及自然语言创建主链修复。

## 变更摘要

- **任务负责人可待定**：`tasks.owner_id` 可空；创建时可先不指派，后续再改；「待定 / TBD」不再误当成真实姓名去查
- **助手写入授权**：口语立项与确认（如「弄个小项目」「好啊弄起来吧」「就按你说的建好」）可授权写入；状态追问（「有没有建好」）不授权
- **`$ref` 契约**：`get_current_user` 同时提供 `id` / `user_id`；`batch_find_users` 支持按姓名引用（如 `owners.示例同事.user_id`）
- **项目代码识别**：「项目：PRJ-1001 示例项目」一类名称中的代码令牌可被接受，不必强制单独提交裸代码
- **批量与草案**：Agent 批量任务回执、计划诊断字段；草案缺负责人降为 warning，可先发布再补齐
- **运行时**：默认 `AGENT_RUNTIME=agentscope`；停止/中断终态不再被「没有查到相关数据」覆盖
- **前端**：指令清单区分步骤成功与业务写入成功，并展示工具名称；甘特/表单支持负责人留空

## 升级

```bash
git pull   # 或解压对应发行包
cp .env.example .env   # 若新增 AGENT_RUNTIME 等变量，按需合并到现有 .env
docker compose up -d --build
docker compose exec backend alembic upgrade head
curl -sS http://localhost/health
curl -sS http://localhost/health/ready
```

新增环境变量（可选，有默认值）见根目录 `.env.example`：

- `AGENT_RUNTIME`（默认 `agentscope`）
- `AGENT_REASONING_ROUNDS`
- `AGENT_TOOL_CORRECTION_ROUNDS`

## 明确边界

- 发布计划草案、确认执行变更方案仍须用户在卡片上操作
- 查无的人员姓名（含错别字）不能静默替换为他人；需先建用户或改正姓名后重试
- 企微真实投递、破坏性故障演练仍依赖独立配置与登记环境
