# Release 0.2.3 — 2026-09-14

Web 界面按可用空间流式排布，助手连续输入更稳，批量写入与多人负责展示对齐。

## 变更摘要

- **页面布局**：去掉 1600/1440 像素上限；项目详情主辅列、助手会话列随容器伸缩；窄屏会话列表改抽屉
- **助手输入**：独立 Composer，输入与发送分行；发送后可续写草稿；上滑阅读时终态不再强制滚回底部
- **解释精简**：长回答默认预览；执行清单成功项可折叠（失败/待核实始终可见）；风险建议与预测/摘要先给结论再展开详情
- **项目详情**：名称优先于编号；编辑/调整/预览改为有边界按钮；新建任务用人员选择代替「负责人 ID」；摘要/进展/预测失败可局部重试
- **移动导航**：底栏固定 5 项（任务、项目、助手、通知、更多），管理员其余入口进「更多」
- **批量写入**：`batch_create_tasks` 接受 `tasks` 别名，缺 `client_item_id` 时自动补齐；规划确认与原文映射更稳
- **多人负责**：任务可有多名 `OWNER`；列表/甘特并列展示；HTTP 环境下不再依赖 `crypto.randomUUID`
- **任务业务编号**：任务可带按日生成的业务代码（如 `T20260914-001`）
- **项目负责人权限**：项目管理权限按「是否为该项目负责人/共同负责人」判定，不再要求全局角色为 PROJECT_OWNER；成员角色的项目负责人可创建任务、指派人员、处理问题与行动项。全局 PROJECT_OWNER 角色仅决定能否新建项目；EXECUTIVE 仍只读
- **可指派人员**：项目负责人选择任务/项目负责人时可选全部在职用户，不再仅限已在项目中有任务的人
- **OA 账号密码登录**（可选，`OA_PASSWORD_LOGIN_ENABLED=true` 开启）：已关联 OA 的用户在登录页直接使用 OA 账号密码，首次登录自动建档；OA 不可用时提示稍后再试，不回退本地密码；OA 初始密码不能登录
- **助手意图与工具组**：写授权改为每轮单点判定，可选 `AGENT_INTENT_MODE=hybrid`（快模型判定 + 正则否决，默认仍为 `regex`）；专项工具按组按需激活（`AGENT_TOOLSETS_ENABLED`，默认开），常驻工具 schema 约减少 36%；每轮输出 `agent.trace` 日志；新增 `python -m app.evals` 评测框架与 `make eval-intent` / `make eval-agent`；修复状态追问时预取事实导致 AgentScope 丢弃历史、规划查询结果含日期时整轮失败、批量创建/更新类参数拼错只在执行时失败、任务负责人更新进度附带原负责人被拒等问题
- **权限代码整理**：`user_is_project_owner` / `project_ids_owned_by` 统一负责人判定与列表过滤；前端 `lib/permissions.ts` 对齐后端门控，去掉页面内重复判断

## 升级

```bash
git pull   # 或解压对应发行包
docker compose up -d --build
docker compose exec backend alembic upgrade head
curl -sS http://localhost/health
curl -sS http://localhost/health/ready
```

入口端口若为 8080，把上述 `localhost` 换成实际 Nginx 地址。本版本无新增必填环境变量；可选 `OA_PASSWORD_LOGIN_ENABLED`（默认 `false`）、`AGENT_INTENT_MODE`（默认 `regex`）、`AGENT_TOOLSETS_ENABLED`（默认 `true`）、`AGENT_TRACE_LOG`（默认 `true`）。

## 数据库迁移

本版本包含 Alembic 修订（按顺序执行即可）：

- `task_business_code`
- `task_participant_owner_role`

## 明确边界

- 发布计划草案、确认执行变更方案仍须用户在卡片上操作
- 未区分负责人/协作人时，助手会按共同负责人写入；仅协作人不会显示为并列负责人
- 助手流式焦点、软键盘避让仍建议在真机上核对；UI 优化不改变后端权限裁决
