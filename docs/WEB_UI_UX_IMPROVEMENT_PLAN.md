## 1. 目标与证据边界

目标：减少解释信息对主要操作的干扰，统一标题、按钮与操作入口，解决助手连续输入和窄屏空间问题，让 Agent 能按文件、行为、验收条件逐项修改代码。

本次完成了以下检查：

- 阅读 `docs/HANDBOOK.md`、仓库指令及 overview / assistant / deploy / antd 技能。
- 审查当前工作区真实页面、公共组件和 CSS；基线 HEAD 为 `2cdb1bd`，不等同于部署构建版本。
- Chromium 加载本机**运行中的 Next.js 前端**，在 1440、1024、768、390px 宽、900px 高的视口检查项目列表、项目详情和项目助手，共 12 个页面/视口组合。
- 按用户补充要求，继续检查 1920×1080、2560×1440、3840×2160、3440×1440 四种大屏/超宽视口，同样覆盖上述三个页面，新增 12 个组合。布局测量原始记录见 [大屏测量数据](assets/uiux-review-2026-09-14/large-viewport-metrics.jsonl)。所有分辨率都是测试样本，不是实现断点或固定容器尺寸。

## 3. 统一设计与实现规则

### 3.0 流式布局原则（新增，覆盖旧版固定像素目标）

用户要求：**布局以百分比和可用空间为基础，适配任意窗口；不按 1080P、2K、4K 分别硬编码页面宽高。** 实施采用 `%`、Flex/Grid 的 `fr`、`minmax()`、容器查询；字号/控件保留可读性与最小触控约束，不随屏幕宽度等比例放大。百分比以所属父容器的内容区为基准，不使用屏幕物理像素计算。

| 层级 | 流式实现约定 | 验收口径 |
| --- | --- | --- |
| 页面外壳 | 全局导航之外的主区 flex:1、min-width:0；业务页面 width:100%、box-sizing:border-box。桌面左右内边距各约可用宽度 2%，窄容器可调为 3%～4% | 标题/概况/数据区域共用内容边界；实际业务内容横向覆盖外壳可用宽度至少 90%，不含专用表单/纯阅读页 |
| 页面宽度上限 | 移除普通业务页面和助手祖先链的 1600px/1440px 像素上限；检查祖先 width、flex-basis、max-width 的共同限制 | 视口变大时业务容器继续增长，不在旧上限形成宽度平台 |
| 项目两列 | 内容宽度扣除 gap 后，主区/辅助区初始约 3:1，用 minmax(0,3fr) / minmax(0,1fr)；间距也计入总宽，不能写 75%+25% 再额外加 gap | 主任务区随空间增长；辅助列放不下标题/控件时切单列，不能无限缩小文字 |
| 助手两列 | 会话侧栏在扣除 gap 后约占面板 18%～22%，对话列占其余空间；支持用户折叠。空间不足时会话列表改抽屉 | 列宽随父容器变化；展开侧栏时对话列至少占净列宽 75%；不能以物理分辨率决定形态 |
| 输入区 | 输入组件占对话列内容区 100%；发送/停止放到下一行操作区，避免占用文本宽度 | textarea 宽度 / 输入区内容宽度 ≥98%（允许边框舍入）；无单独像素最小宽度表 |
| 阅读内容 | 对话列及结构化表格使用可用宽度；纯文字段落可限制约 65～80ch 行长，输入文本区随列宽伸展 | 阅读行长约束只作用于文字，不重新封顶整个面板；长表格可宽于文字并局部滚动 |
| 高度 | 外壳按动态可用视口分配，头部、输入区为 auto，消息区 minmax(0,1fr)/flex:1 与 min-height:0；普通页面随内容增长 | 不按 1080/1440/2160 写固定 height；不因放大输入区百分比而占据大部分屏幕 |

形态切换由容器能否容纳内容决定：实施 Agent 根据导航标签、操作组与正文的最小可读宽度设定少量 **rem/em 容器断点**，并记录依据；不为每个测试分辨率新增媒体查询。侧栏折叠、列数变化允许离散切换，同一形态内必须连续伸缩。保留“可用空间不足 → 抽屉/单列”的降级，不能用纯百分比把控件越缩越小。

字体使用 rem、行高使用无单位值、边距可用比例或带上下限的 clamp；控件点击区和 1px 边框不需要机械改成百分比。百分比高度依赖明确的父高度，优先让 Flex/Grid 分配剩余空间，不能在父高度 auto 时堆叠 height:100%。

### 3.1 优先扩展现有组件

继续使用 Ant Design、`PageHeader`、`AppCard`、`SectionTitle`、`DataToolbar`、反馈组件和现有 theme token。不要另建一套视觉体系或为了此次改造升级依赖。CSS 修改必须限定到应用组件，不全局覆盖所有 `a`、`button`、`svg` 或所有表格。

| 元素 | 目标规则 | 实现落点 |
| --- | --- | --- |
| 页面标题 | 单一 h1；项目名称优先，编号作为辅助标识；标题、状态、主要操作组成同一页面头 | 扩展 PageHeader，保留旧调用兼容；项目页迁移 |
| 分区/卡片标题 | 分区 h2、子区 h3；字重、间距一致；卡片标题使用浅底/底分隔线形成边界，避免同一卡片重复两层标题栏 | AppCard 增加可选 heading level；SectionTitle 支持一致布局 |
| 表头 | 复用浅色 surface、统一 padding/字重/分隔线；正文表格各自滚动，不推宽页面 | theme.Table；Markdown 专属 table 类；业务 Table 按内容配置 |
| 主要操作 | 当前操作组一个默认 primary；保存/提交显示 loading；空输入等不可执行条件明确禁用 | Antd Button；保留既有业务判定 |
| 次要操作 | 编辑、调整、预览等使用有边界 default 按钮；图标加文字；同一区域尺寸一致 | 页面操作组，必要时新增轻量 `ActionGroup` 布局组件 |
| 低频/危险操作 | 删除收至“更多”或独立危险区，仍用 danger，保留删除原因、权限与确认弹窗 | ProjectManagePanel；不改变删除接口 |
| 文中链接 | 仍是链接，具有可辨识颜色、hover/focus 下划线；导航型操作可使用带按钮外观的链接 | 复用 Antd Button href 或 Next Link 样式，最终只产生一个交互元素 |
| 图标与文字 | inline-flex、居中对齐、固定 gap；图标不收缩；文字容器 min-width:0 | 公共标题、操作行、元信息行；避免手工空格/负 top |
| 触控 | 手机主要操作区域至少 44×44px；小图标可扩展点击区，避免相邻重叠 | 作为本项目设计目标，不能只靠全局尺寸 token 推断合格 |

长名称默认允许两行；行内紧凑列表可单行省略，但必须有可通过键盘及触屏访问的完整信息入口，不能只依赖 hover Tooltip。正文用 `overflow-wrap:anywhere` 处理连续英文/URL；代码、表格保留独立滚动。禁止用 `body overflow-x:hidden` 或固定高度裁切来“通过”验收。

### 3.2 信息折叠规则（UX-01 / UX-14）

为解释内容新增可复用 `frontend/components/feedback/ExplanationDisclosure.tsx`，支持 summary、children、默认展开状态与展开计数。组件只负责呈现，不生成新业务结论。

- **普通助手回答**：短答直接展示；已完成长答建议超过 800 字或 12 个非空文本行时提供收起视图。按 Markdown 块边界选取预览，不直接字符串截断表格/代码。无结构化摘要时标注“回答预览”，不冒称完整结论。
- **流式回答**：生成期间不反复折叠和跳动；完成后仅在用户处于末尾、没有选中文本且没有主动展开时应用默认收起；上滑阅读时保留当前展开状态。复制始终复制全文。
- **结构化执行卡片**：默认保留实际创建数量、待处理/失败数量及下一步；成功细项折叠。`needs_review`、UNKNOWN、失败、恢复建议始终可见；不能把“步骤成功”当作“创建任务数量”。
- **风险建议**：默认显示问题摘要、倾向方案、最多 3 条下一步及数据不足/升级提示；原因、核实项、方案全表放入详情。已有 evidence Collapse 继续保留。
- **每日摘要/预测**：默认显示结论、日期差异、关键风险、下一步；关键路径只展示前 3 项和“查看全部 N 项”。预测来源及边界缩为可理解短句，详情展开可见。
- 事实、计算预测、AI 建议、数据不足始终区分；阻断原因、授权确认、完整变更差异不可因“精简”而不可访问。确认前仍须核对既有完整差异。
- 每条消息/记录独立管理展开状态，按稳定 id/版本区分；刷新加载不重置用户当前阅读。不要删数据库全文，不以一次额外 LLM 请求作为折叠前提，不先修改后端 prompt 来掩盖前端问题。

### 3.3 助手输入、焦点和滚动（UX-06 / UX-07）

布局目标：输入区占主对话列可用宽度，文本与发送按钮垂直分区，文本 width:100% / min-width:0；默认桌面 3 行、手机 2 行，最大约 8 行，超出由输入区内部滚动。发送、停止固定可达，不挤压文本宽度。显式展示简短的 Enter 发送、Shift+Enter 换行提示；保留现有中文输入法 isComposing 防护。

会话侧栏按 3.0 的容器空间规则切换抽屉，大屏可折叠；取消旧版“小于 1200px”硬编码要求。使用助手专属布局判断，别修改全站 mobile 断点导致导航联动回归。标题/记忆操作不再继承通用页面头的 260px 文本 flex-basis；手机保持紧凑一行。两个菜单分别标明“导航”和“对话”。

小屏基线测量仅用于描述旧问题，**不作为新代码尺寸**；大屏基线见第 1 节。新验收统一使用 3.0 的相对宽度和内容可达性：

| CSS 视口宽样本 | 当前 textarea 约宽×高 | 改后行为 |
| --- | --- | --- |
| 1440 | 800×36px | 文本区填满所属输入区；默认 3 行 |
| 1024 | 441×36px | 根据内容所需空间切换侧栏；不再要求固定 600px |
| 768 | 322×36px | 根据内容所需空间切换侧栏；不再要求固定 540px |
| 390 | 312×44px | 文本区与发送操作分行；默认 2 行；不再要求固定 320px |

实现建议：抽出 `frontend/components/agent/AgentComposer.tsx`，输入 ref 及交互意图留在页面或专用 hook；不要在 JSX 内堆叠终态副作用。

1. 用户主动发送时记录 conversation id、发送来源与是否允许恢复焦点。请求完成后，等待 textarea 可用的渲染时机再 `focus({preventScroll:true})`。
2. 同一会话、页面可见、用户没有把焦点转到别的控件/弹窗时，正常完成、失败、主动停止后恢复输入。切换会话、离页中止、后台完成、打开记忆/详情或用户正在操作其他区域时不得抢焦点。发送按钮导致的自然焦点转移不算用户主动离开对话。
3. 建议生成时仍可编辑下一条草稿，只禁用重复发送；保留停止按钮。落实前必须把“已发送文本快照”和“下一条草稿”分离：当前 message_start 会清空 input、失败会恢复原 input，必须防止这些回调覆盖新草稿。若分步实施，先修禁用解除后的恢复焦点，再提交允许预输入的独立变更。
4. 发送失败保留未发送内容；新草稿已存在时将原失败消息提供“恢复/重试”入口，不覆盖草稿。空白发送禁用，字符上限可见，不突破现有服务端限制。
5. 滚动跟随用 ref 或等效方式读取最新阅读位置。仅在原先距底部小于现有 80px 阈值时跟随；用户上滑后停止跟随，出现“有新回复 / 回到底部”。终态不得无条件 force；主动发送和主动点击回底可以滚到底部。
6. 保留会话锁、SSE 中止、active-generation 恢复、请求幂等与回答版本逻辑。不要只改 `finally` 里一行 focus 而遗漏停止/重入路径。
7. 手机初次打开不强制弹软键盘；连续发送后的键盘行为需真机验证。输入区/消息区使用可用高度与 safe-area，必要时依据 VisualViewport 处理键盘，不能只增加固定 bottom 值。

### 3.4 项目页、导航及失败态（UX-08～UX-13）

- 项目头按“项目身份与状态 → 主要操作 → 概况/预测 → 任务”排序。计划资料与风险入口移入同一操作组；合并目标、负责人、时间的重复卡片留白。手机预测默认摘要，完整关键路径展开。
- 移动底栏最多 5 个入口：任务、项目、助手、通知、更多；首页、看板、用户管理在更多导航中按原角色权限显示。主入口都无需横滑；更多页当前路由仍有选中反馈。
- EmptyState 增加 compact 变体，用于详情页辅助模块；整页无数据保留现有完整空态。已有 action 插槽复用，任务空态可就近“新建任务”；无权限用户只显示说明。
- 负责人改为可搜索人员选择，复用 fetchAssignableUsers；展示姓名和必要的去重信息，提交仍是现有 owner_id，不顺带改变多人负责语义。加载/失败/空名单都可理解。
- 项目身份/权限为必须成功的数据，摘要、进展、行动项等模块独立 loading/error/retry；空数组仅代表成功且无数据。403 继续正确隐藏/拒绝，不能伪装为空。
- 预测卡失败显示“重新加载”；摘要轮询超时显示“仍在生成，可刷新状态”，不得谎报失败或一直保留无尽 spinner；重试先查询既有 run，避免重复触发生成。
- 搜索、筛选、排序、纯图标按钮有稳定可访问名称；折叠有 aria-expanded；焦点环可见；状态有文字。重要日期/负责人使用正常正文或次级文字 token，不与装饰时间戳同用最淡灰。
- Markdown 项目内链接同页路由跳转；外部链接才新开标签并可辨识。保持安全 Markdown 渲染，不引入 raw HTML；沿用链接协议过滤。

## 5. 验收矩阵

### 数据与视口

固定采样视口用于可重复截图：1920×1080、2560×1440、3840×2160、3440×1440、1440×900、1024×768、768×1024、390×844；增加 320px 极窄和手机横屏。**实现不依赖这些尺寸**：连续拖动窗口和分屏时也必须流式重排。真实手机分别测试键盘打开/关闭及安全区；补测浏览器 125%/150%/200% 缩放及高 DPR。设置 deviceScaleFactor 只能测试像素密度，不等同于浏览器缩放。

演示数据至少包含：80 字项目/任务名、多个负责人、200 字无空格英文串、长 URL、100 条执行清单、20 条风险/冲突、10 列 Markdown 表格、空列表、长回答、多版本回答、成功/失败/UNKNOWN/needs_review 卡片。只使用虚构人员与 `PRJ-1001` 等通用编号。

| 验收 ID | 步骤 | 必须满足 |
| --- | --- | --- |
| AC-01 | 查看短答、长答、成功与异常执行卡；展开/收起/复制 | 长答默认层清晰、全文可访问；失败/待核实和恢复入口始终可见；复制完整原文；不重算/虚构业务结论 |
| AC-02 | 项目详情、风险建议、助手卡片对比 | 标题层级、表头、按钮语义一致；编辑/调整/预览容易识别；无 anchor 内嵌 button 等交互嵌套 |
| AC-03 | 各视口测 textarea 与聊天列 | 达到 3.0 相对宽度目标；默认行数符合约定；发送和停止独立一行不挤压输入；标题/记忆不意外换行 |
| AC-04 | 输入第一条并发送，等待完成后直接键入第二条，不点输入框 | 第二条进入 textarea；失败、停止也能合理继续；连续 5 轮无重复请求或内容丢失 |
| AC-05 | 生成时切会话、打开记忆、聚焦其他控件、切后台；再完成 | 不抢焦点、不弹意外键盘；另一会话不出现上个会话草稿/回复 |
| AC-06 | 生成时编辑新草稿，随后成功/失败/停止；中文输入法确认候选字 | 新草稿不被 message_start/错误回调清除；组成输入不发送；Shift+Enter 换行；空白不发送 |
| AC-07 | 长回复生成中向上滚动至距底部超过 80px，等待 done | 滚动位置不被强制拉回；新回复提示可用；点击回底才恢复跟随；折叠不扰乱当前位置 |

| AC-09 | 手机管理员与成员浏览所有导航；打开键盘发送 | 底栏入口无需横滑，更多里权限正确；输入与当前操作不被键盘遮住；双菜单用途明确 |
| AC-10 | 任务/进展/行动项全空；搜索无匹配 | 紧凑反馈、可执行下一步、清空筛选可达；成功空态和错误态明确不同 |
| AC-11 | 仅摘要/进展/预测接口失败，模拟 403、500、超时与长时间生成 | 项目核心仍可读；局部可重试；不显示伪空数据；摘要超时不无限 spinner 或重复触发生成 |
| AC-12 | ADMIN / EXECUTIVE / PROJECT_OWNER / MEMBER；预览→核对→确认→执行；取消删除 | 权限仍由后端裁决；不可行方案不能确认；确认仍绑定版本/账号；取消删除不发 DELETE；UI 优化无隐式业务写入 |
| AC-13 | Tab/Shift+Tab/Enter/Space；读屏检查标签；色彩检查 | 名称和状态可读，focus 可见；正文对比度目标 4.5:1；焦点/控件边界目标 3:1；关键状态不只靠颜色 |
| AC-14 | 在 1080P/QHD/4K/超宽采样，并连续缩放至样本之间的任意宽度；侧栏开/关 | 业务内容宽/外壳可用宽 ≥90%；助手面板不再停在 1440px；页面不再停在 1600px；列宽按比例增长，正文行长有约束；空间不足时自然转抽屉/单列 |

验收截图必须固定视口、字体条件、数据和状态。记录组件 bounding box 与滚动容器；不要把聊天滚动区中已滚出视口的气泡当成页面溢出。自动检测仅是辅助，需要人工查看截图与实际键盘交互。
